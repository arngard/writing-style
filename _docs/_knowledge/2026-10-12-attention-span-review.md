# 2026-10-12 외부 출력 스타일 Attention Span 검토 사실

2026-10-12 세션에서 외부 출력 스타일 Attention Span을 사용자 지침과 대조해 검토할 때 확인한 사실. 이 자료로 내린 판단은 [_strategy/why-preserve-over-compress.md](../_strategy/why-preserve-over-compress.md)에 있다.

## 대상

- 저장소 alexgreensh/attention-span(GitHub). 검토 시점 기준 별 1,410개, 2026-10-11 갱신, README 배지 기준 AGPL-3.0, 검토한 판은 v0.8이다.
- Claude Code용 출력 스타일 3종(Attention-kind, Spartan, Rundown)과 plugin 형태 설치 수단을 제공한다.

## Attention-kind가 지시하는 것

- 독자의 주의력을 가장 희소한 자원으로 놓고, 응답 하나에서 독자가 흡수하는 양을 최적화한다. 원문은 독자가 ADHD(attention deficit hyperactivity disorder; 주의력결핍 과잉행동장애)라고 단정한다.
- 결론을 첫 문장에 두고, 짧게 쓰고, 실수를 부를 것만 펼친다.
- 범위가 넓으면 가장 중요한 한두 가지만 주고 나머지는 이름만 대고 원하면 주겠다고 제안한다. 큰 작업은 헤드라인과 첫 조치만 말하고 나머지는 묻게 한다.
- 수치, 임계값, 한정 조건을 정확히 옮기고, 경고를 줄이지 않고 그것이 걸린 진술 곁에 둔다.
- 산출물을 요청받으면 산출물만 내고, 진행을 막는 질문은 마지막에 둔다.
- 각 항목을 화살표로 시작하는 문단으로 쓰고, 굵게 표시만 읽어도 답이 전달되게 한다. 쉬운 영어와 따뜻한 어조를 쓰고, 대시와 "X가 아니라 Y" 구문을 금지한다. 표는 5행 미만으로 쓴다.
- 자매 스타일 Rundown은 상태 표시에 이모지를 쓴다.

## 벤치마크 주장과 확인한 사실

- 저장소는 출력이 평균 약 43% 짧아지고, 답이 첫 줄에 오는 비율이 3%에서 75%로 오른다고 주장한다.
- 하네스 코드 `benchmarks/harness/scannability.py`의 `answer_first`는 첫 비어 있지 않은 줄이 `**`로 시작하는지만 검사한다(직접 확인). 따라서 75%는 첫 줄이 굵은 글씨로 시작하는 비율이다.
- 조사 에이전트 보고에 따르면 단축률은 문자 수 기준이고, 정보 보존도와 이해도는 측정하지 않았으며, 벤치마크 문서도 사람 대상 이해도 연구를 대체하지 못한다고 밝힌다.
- 조사 에이전트 보고에 따르면 README의 축약 예시는 출처 없는 "약 90%" 수치를 제시하고, 원문 판본의 트랜잭션과 일관성 논점을 빼먹는다.
