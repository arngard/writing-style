# 2026-11-24 윤문 가속 기법 조사

LLM 에이전트 작업과 코드 편집을 빠르게 하는 기법에 관한 공개 자료의 사실이다. 발견 일자는 모두 2026-11-24이고 수치는 원출처의 주장이다. 자료가 다루는 대상은 일반 LLM 작업과 코드 편집이며, 한국어 윤문에서 같은 효과가 나는지는 이 자료로 확인되지 않는다. 1패스 통합과 규칙별 패스를 직접 비교한 통제 실험은 찾지 못했다. 이 자료로 내린 판단은 [2026-11-24 윤문 속도 개선 설계.md](../strategy/2026-11-24%20윤문%20속도%20개선%20설계.md)에 있다.

## 주요 자료

아래 요지는 검색 결과 요약 기준이며 논문 본문과는 대조하지 않았다.

### 일을 독립된 하위 작업으로 나눠 동시에 돌리고 결과를 모은다

- Anthropic의 글 "Building effective agents"는 병렬화 워크플로의 한 변형으로 sectioning을 든다. 일을 독립된 하위 작업으로 나눠 동시에 돌리고 결과를 코드로 모은다. 고려 사항마다 따로 호출하면 각 측면에 주의를 모을 수 있어 대체로 더 잘한다고 쓰고, 고정된 하위 작업으로 깔끔히 나뉘는 일에 맞는다고 한다. 페이지에는 2024-12 이후 도구가 많이 바뀌었다는 안내가 붙어 있다.
- AWS Prescriptive Guidance의 병렬화 워크플로도 같은 형태(독립 하위 작업, 동시 처리, 결과 합성)를 설명한다.

### 평가한 과제에서 지시가 늘수록 준수율이 떨어졌다

- ManyIFEval와 StyleMBPP(arXiv 2509.21051)는 과제를 고정하고 지시 수만 늘린다(글쓰기 최대 10개, 코드 최대 6개). LLM 10종 모두 지시 수가 늘수록 성능이 크게 떨어졌다고 보고한다.
- IFScale(arXiv 2507.11538, NeurIPS 2025)은 보고서 과제에 키워드 포함 지시를 최대 500개까지 준다. 모델 20종 가운데 가장 좋은 모델도 500개에서 정확도가 70%에 못 미쳤고(결과표 기준 Gemini 2.5 Pro Preview의 68.9%), 앞쪽 지시를 더 따르는 치우침을 보고한다.
- Instruction Stacking Collapse(arXiv 2608.02639)는 검증 가능한 지시를 1개에서 20개까지 쌓아 평가한 세 모델에서 준수율이 약 96%에서 가장 낮게는 20%까지 떨어졌고, 원인이 지시 쌍 사이의 충돌이라고 보고한다. 동료 심사 여부는 확인하지 않은 프리프린트다.

### 전문 재작성 대신 바꿀 곳만 낸다

- Aider 문서는 전문(whole file) 형식이 몇 줄만 바꿔도 파일 전체를 다시 내야 해 느리고 비싸다고 쓴다.
- "To Diff or Not to Diff?"(arXiv 2604.27296)는 diff와 전문 생성 가운데 하나를 고르게 학습한 AdaEdit을 구조를 아는 diff 형식과 함께 쓰면 긴 코드 편집에서 전문 생성과 같은 정확도를 내면서 지연과 비용을 30% 넘게 줄였다고 보고한다. 변경이 전체에 퍼지면 diff의 부담이 전문 생성보다 커질 수 있다고도 쓴다.
- SWE-Edit(arXiv 2604.26102)은 찾아 바꾸기 형식이 정확한 문자열 일치를 요구해 공백 하나만 달라도 실패하고, 국소 변경에는 효율적이지만 재구성에는 깨지기 쉽다고 쓴다.
- JetBrains의 Diff-XYZ 연구(arXiv 2510.12487)는 diff 적용, 역적용, diff 생성 세 과제에서 편집 형식을 비교했다. 강한 모델에서는 찾아 바꾸기 형식이 대부분의 과제에서 가장 좋았고(모든 과제는 아니다), 약한 모델은 다른 형식이 나을 수 있다고 보고한다.

## 추가 출처

아래 요지는 원문과 대조하지 않은 요약이다.

- 패스 통합과 병렬화
  - [Redocly, Use AI to enforce tone and style consistency across docs](https://redocly.com/learn/ai-for-docs/ai-enforce-tone-style-consistency-across-docs): 긴 산문 규칙보다 한 쪽짜리 체크리스트로 한 번에 검사하는 편이 낫다는 주장.
  - [CoEdIT](https://aclanthology.org/2023.findings-emnlp.350/) (EMNLP 2023 Findings): 지시를 받아 여러 편집 과제를 한 모델로 수행하는 연구.
  - [Self-Refine](https://proceedings.neurips.cc/paper_files/paper/2023/hash/91edff07232fb1b55a505a9e9f6c0ff3-Abstract-Conference.html) (NeurIPS 2023): 반복 피드백의 품질 이득.
  - 문장 밖 문맥이 교정에 중요하다는 연구(절 단위 병렬 처리의 위험): [Document-level GEC](https://aclanthology.org/2021.bea-1.8/), [TETRA](https://arxiv.org/abs/2205.11484).
- 패치 형식 출력
  - [Aider, unified diffs](https://aider.chat/docs/unified-diffs.html): 줄 번호 없는 diff나 찾아 바꾸기 블록이 전체 재작성보다 빠르고 생략도 줄었다는 실험.
  - 디코딩 가속(Claude API에는 같은 기능이 없다): [OpenAI Predicted Outputs](https://developers.openai.com/api/docs/guides/predicted-outputs), [해설(업체 주장 3-5배)](https://www.morphllm.com/openai/predicted-outputs), [EfficientEdit](https://arxiv.org/abs/2506.02780), [Blazedit](https://huggingface.co/blog/ganler/blazedit).
- 바뀐 곳만 재검토
  - [reviewdog](https://github.com/reviewdog/reviewdog): 바뀐 줄 주변의 진단만 걸러 보인다.
  - [ERRANT](https://aclanthology.org/P17-1074/) (ACL 2017): 원문과 교정문에서 편집 구간을 뽑는다.
- 기계적 규칙의 결정적 검사 이관
  - [Checkstyle+](https://arxiv.org/html/2510.23068v1) (arXiv 2510.23068): 기계적 규칙은 린터, 언어 이해가 필요한 규칙만 LLM에 맡기고, LLM이 린터가 잡는 단순 서식 위반을 놓쳤다고 보고한다.
  - [Vale](https://vale.sh/), [PostHog 핸드북의 Vale 문서](https://posthog.com/handbook/wizard-and-docs/vale), [Datadog의 Vale 도입기](https://www.datadoghq.com/blog/engineering/how-we-use-vale-to-improve-our-documentation-editing-process.md): 문서 린터와 LLM의 분업.
  - 한국어 자료: [textlint 한국어 규칙 소개](https://wikidocs.net/381081), 형태소 분석기 [kiwipiepy](https://github.com/bab2min/kiwipiepy), 한국어 문법 교정 자료 [Standard_Korean_GEC](https://github.com/soyoung97/Standard_Korean_GEC), [KoGEC](https://arxiv.org/abs/2506.11432), [KAGEC](https://aclanthology.org/2024.findings-emnlp.6/), 규칙 기반을 먼저 쓰는 상용 교정 파이프라인 [바른 AI](https://bareun.ai/docs/en/3.4.0/inside/revision/pipeline).
- 1패스 통합의 준수율 저하
  - [FirstEdit 도움말](https://firstedit.outseta.com/support/kb/articles/OW41Mpmg/why-cant-i-just-use-a-chatbot-like-chatgpt-or-claude-to-enforce-my-house-style) (업체 주장): 긴 스타일 가이드는 뒤쪽 규칙이 무시되기 쉬워 규칙마다 전용 에이전트를 둔다.
  - Lost in the Middle(Liu et al., TACL 2024): 긴 컨텍스트 중간의 정보를 덜 활용한다.
  - [MOSAIC](https://arxiv.org/html/2601.18554v1) (arXiv 2601.18554): 여러 제약을 결합할 때의 지시 준수 측정.
  - [학술지 편집 벤치마크](https://arxiv.org/pdf/2609.11972) (arXiv 2609.11972): 규칙 검색과 면제 규칙 처리를 결정적 기준선과 함께 시험한다.
- 공개 구현: [im-not-ai](https://github.com/epoko77-ai/im-not-ai)(한국어 AI 문체 윤문 스킬), [ste-ko](https://github.com/beamonic/ste-ko)(한국어 통제 언어 규격과 린터), [humanizer](https://github.com/blader/humanizer)(영어 AI 문체 제거 스킬).
- 비용(지연은 줄지 않는다): [프롬프트 캐싱](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), [Message Batches](https://platform.claude.com/docs/en/build-with-claude/batch-processing).
